# 2.7 Criar projeto hr-zuul-server

Zuul é o API Gateway do Spring Cloud: um ponto único de entrada na frente dos microsserviços. Em vez do cliente chamar `localhost:8001` pro hr-worker e `localhost:8101` pro hr-payroll, ele chama só o gateway, que resolve o destino pelo nome registrado no Eureka e repassa a requisição. Isso também é onde autenticação e autorização vão ficar centralizadas mais pra frente.

Projeto criado com Spring Boot 2.3.4 e Java 11, mesma versão dos outros módulos, com três dependências: `spring-boot-starter-web`, `spring-cloud-starter-netflix-eureka-client` (o gateway precisa se registrar no Eureka pra enxergar os outros serviços pelo nome) e `spring-cloud-starter-netflix-zuul`.

Ajustes em relação ao repositório de referência: módulo nomeado `hr-zuul-server` em vez de `hr-api-gateway-zuul`, e groupId/pacote `com.camposcodes`, mesmo padrão já aplicado nos outros módulos. Classe principal `HrZuulServerApplication` com só `@SpringBootApplication`.

`application.properties` ainda vazio e nenhuma rota configurada: só o esqueleto do projeto. `@EnableZuulProxy`, nome da aplicação, porta e as rotas entram na próxima aula.

Build validado com `mvnw test` no JDK 11: `BUILD SUCCESS`, contexto sobe normalmente (os erros de conexão com o Eureka no log são esperados, o hr-eureka-server não estava rodando).

---

#### English

Zuul is Spring Cloud's API Gateway: a single entry point in front of the microservices. Instead of the client calling `localhost:8001` for hr-worker and `localhost:8101` for hr-payroll, it calls only the gateway, which resolves the destination by the name registered in Eureka and forwards the request. This is also where authentication and authorization will be centralized later on.

Project created with Spring Boot 2.3.4 and Java 11, same version as the other modules, with three dependencies: `spring-boot-starter-web`, `spring-cloud-starter-netflix-eureka-client` (the gateway needs to register with Eureka to see the other services by name) and `spring-cloud-starter-netflix-zuul`.

Adjustments relative to the reference repository: module named `hr-zuul-server` instead of `hr-api-gateway-zuul`, and groupId/package `com.camposcodes`, the same pattern already applied to the other modules. Main class `HrZuulServerApplication` with only `@SpringBootApplication`.

`application.properties` still empty and no routes configured: just the project skeleton. `@EnableZuulProxy`, application name, port and the routes come in the next lesson.

Build validated with `mvnw test` on JDK 11: `BUILD SUCCESS`, the context starts normally (the Eureka connection errors in the log are expected, hr-eureka-server was not running).
