# 1.2 Implementar projeto hr-worker

Entidade `Worker` (`tb_worker`), `WorkerRepository` e `WorkerController` implementados. Diferente do curso original, foi adicionada uma camada `WorkerService` entre o controller e o repository (controller não chama o repository direto).

Tratamento de exceção: `ResourceNotFoundException` customizada, `StandardError` como corpo de erro padrão, e `ResourceExceptionHandler` com `@RestControllerAdvice` centralizando o tratamento. `findById` usa `orElseThrow` em vez de `Optional.get()`, devolvendo 404 em vez de 500 quando o id não existe.

Banco H2 em modo arquivo configurado (`AUTO_SERVER=true`, `ddl-auto=create-drop`), com `data.sql` populando 3 registros iniciais. O `AUTO_SERVER=true` foi escolhido de propósito: sem ele, o arquivo do H2 aceita só uma conexão por vez, e a aplicação já rodando bloquearia o acesso pela ferramenta de banco de dados do IntelliJ e pelo console H2. Com essa opção, dá pra ter a aplicação, o IntelliJ e o console H2 conectados ao mesmo banco ao mesmo tempo.

---

#### English

`Worker` entity (`tb_worker`), `WorkerRepository` and `WorkerController` implemented. Unlike the original course, a `WorkerService` layer was added between the controller and the repository (controller does not call the repository directly).

Exception handling: custom `ResourceNotFoundException`, `StandardError` as the standard error body, and `ResourceExceptionHandler` with `@RestControllerAdvice` centralizing the handling. `findById` uses `orElseThrow` instead of `Optional.get()`, returning 404 instead of 500 when the id does not exist.

H2 file-mode database configured (`AUTO_SERVER=true`, `ddl-auto=create-drop`), with `data.sql` seeding 3 initial records. `AUTO_SERVER=true` was chosen on purpose: without it, the H2 file only accepts one connection at a time, and the running application would block access from IntelliJ's database tool and the H2 console. With this option, the application, IntelliJ and the H2 console can all be connected to the same database at once.
