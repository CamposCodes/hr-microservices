# 3.1 Criar projeto hr-config-server

Spring Cloud Config Server é o servidor de configuração centralizada: em vez de cada microsserviço carregar o próprio `application.properties` local, eles passam a buscar as configurações num lugar só, servidas por esse módulo a partir de um repositório Git. Isso permite mudar configuração sem rebuild e sem republicar imagem, ter perfis separados por ambiente (dev, test, prod) e manter segredos fora do código de cada serviço.

Projeto criado com Spring Boot 2.3.4 e Java 11, mesma versão dos outros módulos, com uma dependência só: `spring-cloud-config-server`. Diferente do hr-zuul-server, aqui não entra `spring-boot-starter-web` separado, o starter do config server já traz o web junto.

Ajuste em relação ao repositório de referência: groupId e pacote `com.camposcodes`, mesmo padrão já aplicado nos outros módulos.

`application.properties` ainda vazio e classe principal só com `@SpringBootApplication`: essa aula é o esqueleto do projeto. `@EnableConfigServer`, nome da aplicação, porta e o apontamento pro repositório Git de configurações entram nas próximas aulas.

Build validado com `mvnw test` no JDK 11: `BUILD SUCCESS`, contexto sobe normalmente.

---

#### English

Spring Cloud Config Server is the centralized configuration server: instead of each microservice loading its own local `application.properties`, they start fetching their configuration from a single place, served by this module out of a Git repository. That allows changing configuration without a rebuild and without republishing an image, having separate profiles per environment (dev, test, prod) and keeping secrets out of each service's code.

Project created with Spring Boot 2.3.4 and Java 11, same version as the other modules, with a single dependency: `spring-cloud-config-server`. Unlike hr-zuul-server, there is no separate `spring-boot-starter-web` here, the config server starter already brings web along.

Adjustment relative to the reference repository: groupId and package `com.camposcodes`, the same pattern already applied to the other modules.

`application.properties` still empty and the main class with only `@SpringBootApplication`: this lesson is the project skeleton. `@EnableConfigServer`, application name, port and pointing to the Git configuration repository come in the next lessons.

Build validated with `mvnw test` on JDK 11: `BUILD SUCCESS`, the context starts normally.
